### About

Mostly AI applications and the infrastructure underneath them. I care about
**architecture, latency, and what a system does on a bad day** — not about what
it does in a demo.

I measure before I argue, and I publish what the instrumentation said, including
when it disagreed with me.

```text
Infrastructure  →  Systems  →  AI  →  Production Engineering
```

- **AI application architecture** — retrieval, agent loops, and the plumbing around them
- **Performance & latency engineering** — profile first, then change one thing
- **Production systems & reliability** — failure modes, back-pressure, safe defaults
- **Agentic systems & automation** — task queues, verification gates, auditable state
- **Infrastructure & systems engineering** — storage, distributed services, CLIs
- **Full-stack** when the product needs it
